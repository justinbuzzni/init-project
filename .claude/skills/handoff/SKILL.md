# /handoff — 세션 인수인계

AGENTS.md §2.6 (세션 종료 프로토콜)의 실행판. 목표: **다음 세션이 context.md 하나만 읽고 5분 안에 이어서 작업**할 수 있는 상태를 만든다.

## 절차

1. **작업 상태 파악**: `git status` / `git diff`로 미커밋 변경과 진행 중이던 작업을 확인한다.
2. **커밋 가능하게 마무리**: 테스트가 통과하는 단위로 커밋한다 (커밋 규율은 AGENTS.md §4). 마무리가 불가능하면 `git stash` 후, stash했다는 사실과 내용을 context.md에 명시한다.
3. **context.md 갱신** (진행 중 기능 폴더):
   - 프론트매터: `마지막 갱신`을 오늘 날짜로, `상태`를 실제 상태(`진행중(Phase N)` | `블록됨` | `완료`)로
   - 현재 상태 3~5문장
   - 이번 세션의 핵심 결정 — 이유·기각한 대안·**재검토 조건** 포함
   - **시도했으나 실패한 접근** — 다음 세션이 같은 실수를 반복하지 않도록 반드시
   - **다음 세션 시작점** — `파일경로:함수명` 수준으로 구체적으로, 주의사항(함정·미완성 부분·stash 여부) 포함
4. **tasks.md 동기화**: 체크 상태를 실제 완료 상태와 일치시킨다.
5. **교훈 자산화** (메모리 레이어가 있으면, AGENTS.md §2.8):
   - 이번 세션의 시행착오 중 일반화되는 교훈이 있으면 `mem-lesson-save`로 저장 (없으면 건너뜀 — 억지로 만들지 말 것)
   - `mem-checkpoint-create`(targetType=session, label="[기능명] Phase N 상태")로 재개 지점 저장
   - 메모리 도구 실패는 무시하고 진행 (가속기이지 의존성이 아님)
6. **문서 커밋**: `[structural] 세션 인수인계: [기능명]` 형식으로 커밋한다.
7. **요약 보고**: 사용자에게 한 문단으로 — 완료된 것 / 남은 것 / 다음 시작점.
8. **기능이 완전히 끝났다면**: Phase 3 아카이빙을 제안한다 — 핵심 결정을 ADR/`ARCHITECTURE.md`로 승격 → context.md `상태: 완료` → 폴더를 `specs/_archive/`로 이동. 회고가 쌓였으면 `/learn`으로 승격 후보 검토도 제안.
