# Conventions

> 마지막 갱신: YYYY-MM-DD
> 코딩 컨벤션, 명명 규칙, 그리고 **검증 루프의 공식 명령어**를 정의한다.
> ⚠️ 프로젝트 시작 시 아래 placeholder를 실제 명령어로 채우세요. "될 것 같다"가 아니라 이 표의 명령어가 통과해야만 완료다.

## 프로젝트 명령어 (검증 루프)

| 목적 | 명령어 | 실행 시점 |
|------|--------|----------|
| 테스트 (전체) | `[예: pytest / npm test]` | 커밋 전 필수 |
| 테스트 (단일) | `[예: pytest path::test -x]` | TDD 루프 중 |
| 린트/포맷 | `[예: ruff check / eslint]` | 커밋 전 필수 |
| 타입 체크 | `[예: mypy / tsc --noEmit]` | 커밋 전 필수 |
| 빌드/실행 | `[예: make build]` | 필요 시 |

- 테스트가 느리면 TDD 루프 중에는 관련 테스트만, 커밋 전에는 전체 실행

## 명명 규칙

- (예: 파일명 snake_case, 클래스 PascalCase, 테스트 파일 `test_*.py`)
- (예: 테스트 이름은 동작을 설명 — `shouldSumTwoPositiveNumbers`)

## 코딩 컨벤션

- (예: Early Return 선호, 함수형 인자 전달 방식, 에러 처리 방식)
- (예: 포맷터 설정 파일 위치 — 포맷은 도구가 결정, 사람이 논쟁하지 않음)

## 디렉토리/구조 컨벤션

- (예: 기능별 폴더 구조, 테스트 위치)
