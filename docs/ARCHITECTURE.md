# Architecture

> 마지막 갱신: 2026-11-11
> 스타터 저장소 자체의 구조다. 소비 프로젝트에는 빈 양식 [specs/_templates/ARCHITECTURE.md](../specs/_templates/ARCHITECTURE.md)가 복사된다.

## 시스템 개요

init-project는 에이전트 지침·스킬·문서 템플릿·리마인더 훅을 배포하는 저장소다.
애플리케이션 서버·DB·공개 API는 포함하지 않는다. 서브모듈 배포 결정은 [ADR-001](adr/001-submodule-distribution.md)에 있다.

## 모듈 구조와 경계

| 구성 | 책임 | 위치 |
|------|------|------|
| 공통 정책 | 자율성·승인·완료 기준 | AGENTS.md |
| 에이전트 연결 | 공통 정책 참조와 훅 연결 | CLAUDE.md, .claude/settings.json |
| 선택적 절차 | 계획·인수인계·회고 | .claude/skills/ |
| 리마인더 | 기능 탐색·편집·커밋 안내 | .claude/hooks/ |
| 배포 | 기존 파일을 보존하며 문서 복사·심링크·설정 생성 | scripts/bootstrap.sh |
| 문서 | 스타터 사실·진행 상태 | docs/, specs/ |
| 양식 | 기능 문서·ADR과 소비 프로젝트 docs의 빈 양식 | specs/_templates/ |

## 의존성 방향

- 스킬·템플릿·README·훅 안내는 AGENTS.md의 정책을 사용한다.
- 훅은 lib/common.sh를 사용해 소비 프로젝트의 specs를 읽는다. 정책 승인 여부를 강제하는 엔진이 아니다.
- bootstrap은 specs/_templates의 docs 양식을 복사하고 템플릿·스킬은 심링크, 훅은 경로 참조로 연결한다. 기존 파일은 자동 병합하지 않는다. 스타터의 docs/는 배포 입력이 아니다. 기존 settings.json에 없는 스타터 훅은 재실행 시 이름으로 안내한다(jq가 있을 때).
- 공통 정책 변경 시 스킬·템플릿·훅 문구의 일관성을 검토한다. 훅 변경은 별도의 코드 검증이 필요하다.
- SessionStart는 등록된 CML 훅의 package.json을 읽어 안내 방식을 선택한다. Node 실행이나 MCP 질의는 하지 않는다. 설정·버전이 불확실하면 안내만 생략한다.
- SessionStart는 context 프론트매터를 단일 awk 프로세스로 읽고 같은 갱신 날짜의 경과 일수를 재사용한다. 날짜 파싱 후 현재 시각을 구하는 순서를 유지해 날짜 경계에서 안내가 달라지지 않게 한다.
- 네 훅은 진행 중 기능을 같은 기준으로 판정한다. 상태 프론트매터가 있고 완료가 아닌 context만 추적하며, 프론트매터 없는 레거시 문서는 어떤 리마인더도 만들지 않는다. 재검토: 프론트매터 없는 문서를 추적해야 하는 소비 프로젝트가 생길 때.
- 커밋 리마인더는 HEAD 커밋이 최근 600초(Bash 도구 최대 실행 시간) 안에 만들어졌을 때만 검사한다. 명령 문자열만으로는 새 커밋 여부를 알 수 없기 때문이다.
- SessionStart 컨텍스트에는 최근 갱신 순 20건과 나머지 건수만 싣고 전체 목록은 `session_start.sh --all`로 본다. 수십 KB 출력은 Claude Code가 파일로 빼서 앞부분만 전달하기 때문이다. 재검토: 훅 출력 한도가 바뀌거나 진행 문서가 대부분 20건 이하일 때.
- tests/hooks/는 설정과 마커 디렉터리를 주입해 실제 사용자 설정과 격리한다. 편집·Stop 리마인더는 세션별 30분 간격으로 제한한다.
- tests/bootstrap/는 필요한 배포 입력만 임시 소비 프로젝트로 복사해 기본 경로의 산출물·보존·재실행 계약을 검사한다. tests/guidelines/는 스타터 유지보수용 수동 행동 평가 자료이며 bootstrap으로 배포하지 않는다.

## 데이터 저장소와 스키마

애플리케이션 데이터 저장소는 없다. 메모리 MCP는 선택적 연결이다.
context.md의 기능·상태·마지막 갱신 프론트매터는 훅이 읽으므로 변경 시 소비 경로를 함께 검토한다.
