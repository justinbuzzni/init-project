# Claude 시작 안정성 Plan

> 근거 문서: [spec.md](./spec.md)

## 아키텍처 영향

기존 Happy SDK 인증 경계와 init-project 훅 모듈 안에서 수정한다. 외부 의존성·데이터 스키마·권한 변경은 없다. Happy는 현재 작업공간의 `.aplus/worktrees/happy-claude-startup-fix` 별도 체크아웃에서 수정하며 기반은 로컬 `happy` 저장소의 `origin/main`이다.

## 접근 방식

초기화 예산은 60초로 분리한다. 인증 검사는 생략하지 않으며 진단은 정해진 단계·사유만 허용한다. 훅은 프론트매터를 일괄 추출하고 날짜별 계산을 재사용한다. 무제한 대기·전역 시간 제한 확대·훅 비활성화는 선택하지 않는다.

## 단계

- [x] Phase 1: 실패 회귀 테스트 → 초기화 예산·오류·진단 수정 → SDK 검증.
- [x] Phase 2: 훅 결과·프로세스 수 회귀 테스트 → 일괄 스캔·날짜 캐시 → 훅·bootstrap 검증.
- [x] Phase 3: 문서·인수인계 동기화 및 적용 범위 보고.

## 검증과 복구

Happy의 기존 Vitest·타입 검사를 사용하고 실제 SDK는 로컬 더미 토큰/서버로 확인한다. init-project는 CONVENTIONS.md의 훅·bootstrap 명령을 실행한다. 설치본을 건드리지 않으므로 복구는 두 체크아웃의 해당 diff를 되돌리는 것이다.

## 실행 근거

사용자가 앞선 추천안대로 수정을 요청했다. 요청 안의 호환 가능한 수정으로 진행하며 외부 발행·설치본 변경은 별도 범위다.
