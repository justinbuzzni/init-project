# pstack 검증 관점 도입 Context

## 현재 상태

지정한 Claude Fable 5.1 high 리뷰를 수집하고 템플릿·bootstrap 회귀 검사·수동 행동 평가 자료를 보완했다. bootstrap 실행 동작과 AGENTS.md의 권한 정책은 변경하지 않았다. 행동 평가 자료 준비는 완료됐고 실제 모델 비교 실행은 수행하지 않았다.

## 핵심 결정 로그

- [2026-10-18] plan에는 소비 경로와 검증할 가정·확인 방법만 추가 / 이유: 실제 검증 결과는 기존 context의 책임이므로 중복하지 않음.
- [2026-10-18] 테스트는 필요한 배포 입력만 복사 / 이유: 작업 트리 전체 복사에 섞이는 사용자 파일과 git 메타데이터를 제외하고 미커밋 배포 입력은 검사하기 위함. 파일 목록은 bootstrap 입력 계약이 바뀔 때 재검토.
- [2026-10-18] 수동 행동 평가는 단계 연속 실행 사례 하나와 사용자 지정 정지 대조 조건으로 축소 / 이유: 자동 평가 실행기 없이 관측 가능한 행동을 먼저 정의. 반복 사용 수요가 생기면 확장 검토.

## 리뷰 반영

- 리뷰 세션: cmvdp7a40669a152fkuub27tx, claude-fable-5-1 / high. turn-end 후 결과를 읽었다. Desktop 표시 여부는 확인하지 않았다.
- 반영: plan 중복 축소, 사용자 파일을 제외한 테스트 입력 복사, 산출물 목록·체크섬·링크 대상의 재실행 전후 비교, 기존 파일 보존, 부분 배포 재실행, 소규모 수동 평가.
- 조정: 리뷰의 git 추적 파일 전체 복사 대신 실제 배포 입력을 명시적으로 복사했다. 새 스킬 등 미커밋 입력도 검사할 수 있고 현재 배포에 필요한 경계를 드러낸다.
- 보류: 행동 평가 모델 실행은 이번의 사례 준비 범위에 포함하지 않았다. 효과를 실측했다고 주장하지 않는다. 자동화가 원천적으로 불가능한 것은 아니며, 현재 실행기를 도입하지 않은 것이다.

## 발견된 문제 / 열린 질문

- 리뷰에서 비기본 서브모듈 경로의 `#`과 sed 구분자 충돌 가능성을 지적했다. 이번에는 기본 배치만 검증하며 해당 경로 지원 변경은 하지 않았다.
- Linux·Windows, 비기본 배치, 파일 쓰기 도중 강제 종료는 미검증이다.

## 파일 맵

- specs/_templates/plan.md — 소비 경로·안전성 가정의 확인 계획.
- tests/bootstrap/run.sh — 배포 입력 격리, 산출물·보존·부분 상태·멱등 검사.
- tests/guidelines/README.md — 유지보수자용 수동 행동 평가 사례와 기록 방법.
- docs/CONVENTIONS.md, docs/ARCHITECTURE.md — 검사 범위와 배포 경계.

## 검증·승인 상태

- 통과(Darwin): bash tests/hooks/run.sh, bash tests/bootstrap/run.sh.
- 통과: bootstrap 러너 셸 구문, 설정 JSON, git diff --check, 변경 문서의 상대 링크와 context 프론트매터.
- 검증 강도 확인: 격리된 사본에서 MCP 설정 복사 누락, 템플릿 링크 손상, 기존 AGENTS.md 덮어쓰기 결함을 각각 주입했을 때 러너가 모두 실패했다. 실제 bootstrap 소스는 수정하지 않았다.
- 미실행: 수동 행동 평가의 모델 비교. 자료 준비만 완료로 판정했다.
- 승인 근거: pstack 제안에 대해 지정 모델로 리뷰하고 개선하라는 사용자 요청. 남은 승인 대상 없음.
